## この記事について

AI企業・クリスタルメソッド株式会社で、Claude Code を日々の業務で使っているチームの記録です。

2026年10月20日に、Claude Code v2.1.304 を**まっさらなフォルダにインストールし、初めて起動して、1つ作業を頼むまで**を実際に操作して録画しました。そのとき、初めて使う人が手を止めそうな場所が3か所ありました。画面はすべて実際の出力そのままです（Linux・Opus 5.5・Claude Max プラン）。

使ったのは、HTML・CSS・JavaScript の3ファイルだけの小さな練習用フォルダです。

## 全体の流れ（約1分の動画）

1. 公式のコマンド1行でインストールする
2. 作業フォルダで `claude` と打って起動する
3. 日本語で「このフォルダに何があるか説明して」と頼む
4. 「見出しの色を青に変えて」と頼み、変更内容を確認してから書き換えてもらう

## つまずき1：インストール直後に「PATH が通っていない」と出る

公式のインストールコマンドはこれだけです。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

実行すると `Claude Code successfully installed!` と出ますが、今回の環境ではその下に **Setup notes** として「`~/.local/bin` が PATH に入っていない」という注意が出ました。この状態で `claude` と打っても「コマンドが見つからない」になります。

![公式のインストールコマンドを実行し、PATHが通っていないという注意のあと export を実行して claude --version で 2.1.304 と表示されたターミナル画面](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-01-install-20261020.png)

画面に出ているとおり、`export PATH="$HOME/.local/bin:$PATH"` を実行してから `claude --version` を打つと、`2.1.304 (Claude Code)` と表示されました。ターミナルを開き直すたびに必要にならないよう、表示された案内どおり、シェルの設定ファイル（bash なら `~/.bashrc` など）にこの1行を書き足しておきます。

## つまずき2：最初の「フォルダを信頼するか」は No が選ばれている

作業フォルダで `claude` と打つと、最初に「このフォルダを信頼するか」を聞かれます。今回のバージョンでは、**最初に選ばれているのは `No, exit`** でした。

![Claude Code を新しいフォルダで初めて起動したときのフォルダ信頼の確認画面。最初は No, exit が選ばれている](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-02-trust-default-20261020.png)

私たちも最初の録画では、そのまま Enter を押して Claude Code が終了してしまいました。自分で作ったフォルダなら、**下矢印キーで `Yes, I trust this folder` に合わせてから Enter** を押します。

![下矢印キーで Yes, I trust this folder を選んだフォルダ信頼の確認画面](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-03-trust-yes-20261020.png)

ダウンロードしてきた中身の分からないフォルダでは、No を選んで先に中身を確かめるのが安全です。

## つまずき3：ファイルを見るだけでも許可を求められることがある

今回は、Claude Code が何をしようとしているかを1つずつ確かめるため、`claude --permission-mode manual`（手動で承認するモード）で起動しました。

「このフォルダに何があるか、初心者にもわかるように短く説明して」と頼むと、3つのファイルの中身を表示するコマンドを実行してよいか聞かれました。画面には「このコマンドの変数は実行前に確認できない」という理由が出ています。

![手動モードで「このフォルダに何があるか説明して」と頼んだとき、ファイルの中身を表示するコマンドの実行許可を求められた画面](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-04-bash-permission-20261020.png)

壊れる操作ではないので `1. Yes` で許可しました。そのあと、ファイルごとの役割（ページの骨組み・見た目・動き）を表にまとめて答えてくれました。何度も聞かれるのが面倒な場合は、画面の2番目の選択肢から自動で判断するモード（auto mode）に切り替えられます。慣れるまでは、何をしようとしているかを読んでから許可するほうが安心です。

## 実際に作業を任せる：変更前と変更後を見せてから書き換える

続けて「見出しの色を青に変えて」と頼みました。Claude Code は `style.css` を読み、**書き換える前に変更前（赤）と変更後（緑）を並べて**、書き換えてよいか確認してきます。

![「見出しの色を青に変えて」と頼んだあと、style.css の変更前と変更後を並べて書き換えてよいか確認している画面](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-05-edit-confirm-20261020.png)

`1. Yes` を選ぶと書き換わり、何をどう変えたか（`#333333` の濃いグレーから `#0066cc` の青へ）を日本語で報告してくれました。

![style.css の見出しの色を #333333 から #0066cc に変え、変更内容を日本語で報告している画面](https://crystal-method.com/wp2020/wp/wp-content/uploads/2026/10/cc-first-run-06-edit-done-20261020.png)

起動から書き換えの報告まで、この練習用フォルダでは1分弱でした。

## まとめ

- インストール後に PATH の注意が出たら、表示された `export` の行を実行し、設定ファイルにも書き足す
- フォルダ信頼の確認は、最初に `No, exit` が選ばれている。自分のフォルダなら下矢印で Yes を選ぶ
- 手動モードでは、ファイルを読むだけのコマンドでも許可を求められることがある。何をするかを読んでから許可する
